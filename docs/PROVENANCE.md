# Provenance: what this repository is and how to check it

This repository holds the **Kerneta Engine V4.4n with its measured results**. The
engine and its evidence have not changed since the release run on 2026-08-16.
Everything around them, the CLI, the hooks, the MCP server, the store system and
the documents, is versioned and has moved on; the version string is in
`lib/version.js`. Nothing in it is a re-run, a re-ingest or a re-score of
anything: every number traces to a file under `run-artifacts/`.

## The chain of custody

| step | what | evidence |
|---|---|---|
| 1 | Release run: 500 LongMemEval-S questions, actor `openai:gpt-4o` at temperature 0, stores built fresh (19,195 sessions) | `run-artifacts/lme.run.json`, `run-artifacts/lme.hypotheses.jsonl`, `run-artifacts/lme.hypotheses.jsonl.eval-results-gpt-4o` |
| 2 | Scored by the benchmark authors' `evaluate_qa.py`, judge snapshot `gpt-4o-2024-08-06`: **83.00%** (415/500) | the `.eval-results-gpt-4o` file, one verdict per question |
| 3 | Same 500 rendered prompts answered by four Claude models through `lib/providers/manual.js`, judged identically | `run-artifacts/lme.<actor>.hypotheses.jsonl` and their `.eval-results-gpt-4o` files |
| 4 | Retrieval side proved identical for all five actors | `run-artifacts/lme.rows.jsonl` is byte-identical across the five runs, sha256 `95bcf659c42ff063...` |
| 5 | Retrieval-only recall sweep, k = 1 to 15, over the same stores and cached vectors, zero network calls | `experiments/recall-sweep/results/` |

Steps 1 to 6 changed no engine file, no run artifact and no score. Step 7 is
everything since, and it changed nothing that a number rests on: the engine
file `lib/methods/daidocs-v44n/method.js` and every file under `run-artifacts/`,
`benchmark/` and `experiments/recall-sweep/results/` hash to the same values in
every release since the run. The rest of `lib/` is not fixed: the providers,
the store system, the registry and the host detection have all changed, and none
of them touches a score.

## Verify it yourself

`MANIFEST.sha256` lists a sha256 for every shipped file as of the lock named in
its header. Recompute and compare:

```bash
grep -v '^#' MANIFEST.sha256 | grep -v '^git-HEAD' | sha256sum -c --quiet
```

```powershell
Get-Content MANIFEST.sha256 | Where-Object { $_ -notmatch '^#' -and $_ -notmatch '^git-HEAD' } | ForEach-Object {
  $h, $f = $_ -split '\s+', 2
  $got = (Get-FileHash -Algorithm SHA256 $f).Hash.ToLower()
  if ($got -ne $h) { "MISMATCH $f" }
}
```

No output means every listed file is byte-identical to the copy the manifest describes.

Two things to know when verifying:

- **Verify from this folder, not from a fresh clone on another platform.** Some
  artifacts carry CRLF endings and `.gitattributes` may normalise them on
  checkout, which changes the hash without changing the content. A clone made
  on Windows with the same autocrlf setting matches; if yours does not, diff the
  file with `git diff --ignore-cr-at-eol` before concluding anything changed.
- **The manifest predates the publication commits.** To verify every hash at
  once, check out `c4629c2` (`git checkout c4629c2`) and run the command above
  there; that tree matches the manifest completely. On `main`, the files edited
  or added by publication (`README.md`, `CHANGELOG.md`, `CITATION.cff`,
  `package.json`, `package-lock.json`, `tools/make_charts.py`,
  `tools/references.json`, `assets/charts/README.md`, `docs/RESULTS.md`, this
  document, the two new charts and `experiments/`) will differ; nothing under
  `run-artifacts/`, `benchmark/`, `lib/`, `spec/` or `prompts/` does. Every file
  that carries a measured number is listed and unchanged.

## What the numbers rest on

- **Dataset:** LongMemEval-S, cleaned variant, all 500 questions including the
  30 abstention items. Not redistributed here; obtain it from the benchmark
  authors and follow [`REPLICATION.md`](REPLICATION.md).
- **Engine:** `lib/methods/daidocs-v44n`, ingest signature `daidocs-4.4.1`,
  routing by the shipped regex `classify()`.
- **Observer:** `openai:gpt-4.1-mini`. **Embedder:** `openai:text-embedding-3-small`.
- **Tokenizer:** `gpt-tokenizer@3.4.0`, pinned exactly, used on both sides of
  every token ratio.
- **Judge:** `evaluate_qa.py` from the LongMemEval repository, snapshot
  `gpt-4o-2024-08-06`.

## What would falsify a claim here

- A recomputed hash that does not match: the artifact was edited after freezing.
- A `check_numbers.mjs` failure: a document quotes a figure no artifact backs.
- A reproduction under [`REPLICATION.md`](REPLICATION.md) that lands outside
  about two standard errors (roughly 3.4 points at n=500) of 83.00% with the
  same actor, judge and observer: open an issue with the per-question diff. That
  is the most valuable issue this project can receive.
