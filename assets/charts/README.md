# Charts

Generated by `tools/make_charts.py`, only after a benchmark run has been
published via `tools/publish_run.mjs`. No chart ships before the run, so no
chart can ever disagree with a measurement: `tools/check_numbers.mjs` fails the
build if a rendered chart exists in the pre-run state or carries a figure the
run artifacts do not back.

Five charts ship:

| file | what it shows | values come from |
|---|---|---|
| `headline` | the release-run accuracy | `tools/publish_run.mjs` output |
| `categories` | accuracy per question type | same |
| `tokens` | tokens read vs tokens pasted | same, plus the corpus constant |
| `actors` | five answering models over the identical memory layer | `RESULTS-ACTORS.md`, backed by `run-artifacts/lme.<actor>.hypotheses.jsonl.eval-results-gpt-4o` |
| `recall` | recall@k, k = 1 to 15, content and pick definitions | read at generation time from `experiments/recall-sweep/results/recall-at-k.json` |

No leaderboard chart exists, deliberately. Third-party figures stay as data in
`tools/references.json`.

## The look

The charts are drawn on the daidocs.com chart surface, not on matplotlib's
default. `tools/chart_theme.py` ports it: the palette is transcribed from
`daidocs-site/assets/theme.css`, and the bar treatment, gradient stops and glow
colours from the site's `assets/fx-2040.css`. A chart in this README should be
recognisably the same graphic as one on the site.

Two rules carry meaning and are not decoration:

- **The accent gradient marks the row being pointed at**, the mint to green to
  blue of `.s-aidoc`, with its halo. Everything else that is ours sits in the
  cooler steel of the same family. `categories` therefore has no accent row at
  all: the point of that chart is the spread with the worst rows included, and
  giving all six the celebratory treatment would work against it.
- **Warm means cost.** `.s-full` orange to red is only ever the comparison arm,
  which is why `tokens` reads at a glance before the labels are.

Charts render on a dark card rather than on transparency, so they read as an
intentional panel on the light and the dark GitHub theme alike instead of as a
smudge on one of them.

One thing does not match the site: the fonts. Plus Jakarta Sans and Commit Mono
are served as woff2, which matplotlib cannot read, and no TTF or OTF of either
is in the repository. The stacks in `chart_theme.py` name the brand faces first
and fall through to whatever the rendering machine has, ending at matplotlib's
bundled DejaVu, so a build never fails for a missing font. Charts built on a
machine without the brand faces are correct in every respect but the
letterforms.
